Below, you can read information on some challenges I faced when working at kShuttle.

**Challenge 1: Building a Documentation Portal from scratch with MadCap Flare for the CSR Insight software**

Initially, the Product team maintained two guides, one for end users and the other for administrators, briefly explaining how the CSR Insight software worked. As these guides were insufficient for users' documentation needs, I was hired to set up online help for the CSR Insight software using MadCap Flare. 

When I arrived, a technical writer from another team helped me create the documentation portal by choosing a template and performing basic customization. 

After a month, I took over the entire project.

Before starting to design documentations, I carried out the following actions:
- Establishing writing standards by creating a style guide
- Performing advanced customization of the documentation portal
- Establishing processes and managing the entire documentation lifecycle (planning, production, proofreading, publication)

**Challenge 2: Catching up and continuously improving the Documentation Portal as the team's sole technical writer**

Based on feedback gathered from my users (colleagues, customers, and partners) during feedback campaigns and team meetings, two areas for improvement were identified:
- Fill out the documentation portal in its entirety, that is, creating documentation for each screen (quantitative requirement)
- Providing more detailed information for existing documentation (qualitative requirement)

Issues I had to deal with in order to meet these requirements:
- Technical writing is an unfamiliar field for my colleagues.
- The pace of software feature production (design, development, publication) is extremely fast compared to the pace of documentation production
- The large number and complexity of screens to be documented
- The lack of availability of my colleagues

Actions taken to resolve these issues:
- Explaining what is a technical writer and formulating documentation needs
- Implementing monitoring tools and continuously improving processes
- Planning documentation as early as possible and prioritizing tasks
- Organizing a weekly information meeting with several SMEs (Product Owners, Lead Developer)
- Frequently communicating with consultants to keep up with clients' needs

**Challenge 3: Making the Documention portal accessible to customers and partners**

Initially, the CSR Insight Documentation Portal was only accessible to internal users, mainly consultants. Clients and partners could not access the Documentation Portal.

To resolve this issue, the Product Owners and the Lead Developper helped me find a way to access the Documentation Portal from within the software.

**Challenge 4: Improving the navigability of the Documentation Portal**

Some users reported difficulties finding specific information within the Documentation Portal. 

To resolve this issue, I added version icons, search tips, internal links between related documents, and so on.

**Challenge 5: Improving users' basic understanding of the software**

To help users undestanding better how to use the software, improving basic comprehension is necessary. 

To resolve this issue, I created a "Quick Start" menu containing business documentation with key concepts information (for example, "Carbon Footprint"), as well as a glossary to define essential terms.

**Challenge 6: Improving the readability of the Documentation Portal**

Some users identified readability issues.

To resolve this issues, I changed the font type, improved spacing between paragraphs, and divided heavy documents into several ones (for example, for the "Generation of Regulatory Reports", there are 4 documentations).
