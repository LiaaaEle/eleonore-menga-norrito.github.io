Data is collected or calculated on indicators periodically (yearly, half-yearly, quarterly, or monthly) and at a certain level of the entity hierarchy (parent and child entities) within campaigns. To collect data, go to the Data Collection Campaigns screen.

 

On Reporting screens, data is consolidated over the different periods of the year (data consolidation on period hierarchy) as well as at the parent entity level (data consolidation on entity hierarchy).

 

Data consolidation is carried out using aggregations methods:

  • Whether the indicator is collected or calculated, data is consolidated across the period hierarchy using a temporal aggregation method. If collected, also across the entity hierarchy.

  • For calculated indicators, data is also consolidated across the entity hierarchy using an entity aggregation method.

 

STEP BY STEP

For each indicator, you must provide information on data typology from the Data typology block of the Identity card or the Data typology column. See Indicator Management: Data Typology Column.

Selecting aggregation methods is part of required information on data typology.

When creating or editing an indicator:

  1. Select a temporal aggregation method whether your indicator is collected or calculated.

    NOTE This first method determines how data will be consolidated over periods. It is also used for consolidating data across entities when the entity aggregation method is Compute at level 0 then aggregate.

  2. Select also an entity aggregation method if your indicator is calculated.

    NOTE This second method determines what will be used for data consolidation across entities: only the indicator calculation formula or the indicator calculation formula at the data collection point then the temporal aggregation method.

Temporal Aggregation Methods

TIP  To help you understand how each temporal aggregation method works, read the examples.

 

NOTE For aggregation calculation to work, indicators, whether calculated or collected, must be deployed on the same entity.

 

To consolidate data across period and entity hierarchies, you must first to choose one of the following temporal aggregation methods:

  • Average:

    • Aggregated data across the period hierarchy is the average of the data collected on each period for an entity.

    • Aggregated data at the parent entity level is the average of the data collected for each child entity, from the data collection point (called Collect level in the CSR Insight application) to the highest entity level.

    • France, Spain, China, and Japan are country entities (country level) and Europe and Asia are continent entities (continent level).

    • France and Spain are the child entities of Europe.

    • China and Japan are the child entities of Asia.

    • Data is collected on an indicator twice a year (once in the first semester HY1, once in the second semester HY2) at country level.

    • The following data has been collected for this indicator at the country level:

       

    Data consolidated using the Average temporal aggregation method:

    • Aggregated data on period hierarchy will be the average of the data collected each half-year for an entity.

    • Aggregated data on entity hierarchy will be the average of the data collected for each country entity.

     

  • Sum:

    • Aggregated data across the period hierarchy is the sum of the data collected on each period for an entity.

    • Aggregated data at the parent entity level is the sum of the data collected for each child entity, from the Collect level to the highest entity level.

    Example

    • France, Spain, China, and Japan are country entities (country level) and Europe and Asia are continent entities (continent level).

    • Data is collected on an indicator twice a year (once in the first semester HY1, once in the second semester HY2) at country level.

    • The following data has been collected for this indicator at the country level:

       

     

    Data consolidated using the Sum temporal aggregation method:

    • Aggregated data on period hierarchy will be the sum of the data collected each half-year for an entity.

    • Aggregated data on entity hierarchy will be the sum of the data collected for each country entity.

     

  • Minimum:

    • Aggregated data across the period hierarchy is the smallest value among the data collected on each period for an entity.

    • Aggregated data at the parent entity level is the smallest value among the data collected for each child entity, from the Collect level to the highest entity level.

    Data consolidated using the Minimum temporal aggregation method:

    • Aggregated data on period hierarchy will be the smallest value among the data collected each half-year for an entity.

    • Aggregated data on entity hierarchy will be the smallest value among the data collected for each entity.

     

  • Maximum:

    • Aggregated data across the period hierarchy is the largest value among the data collected on each period for an entity.

    • Aggregated data at the parent entity level is the largest value among the data collected for each child entity, from the Collect level to the highest entity level.

    • Aggregated data on period hierarchy will be the largest value among the data collected each half-year for an entity.

    • Aggregated data on entity hierarchy will be the largest value among the data collected for each entity

     

  • Last known value:

    • Aggregated data across the period hierarchy is the last data you collected for an entity.

    • Aggregated data at the parent entity level is the sum of the data collected for each child entity (or the average if the indicator’s unit is a percentage), from the Collect level to the highest entity level.

    • Aggregated data across the period hierarchy is the square root of the sum of the squared data collected on each period for an entity.

    • Aggregated data at the parent entity level is the square root of the sum of the squared data collected for each child entity, from the Collect level to the highest entity level.

    • Aggregated data on entity hierarchy will be the square root of the sum of the squared data collected for each country entity.

     

  • Average excluding null values (0):

    • Aggregated data across the period hierarchy is the average of the data collected on each period for an entity, excluding null values (0).

    • Aggregated data at the parent entity level is the average of the data collected for each child entity, from the Collect level to the highest entity level, excluding null values (0).

Entity Aggregation Methods

TIP  To help you understand how each entity aggregation method works, read the examples.

 

NOTE For aggregation calculation to work, indicators, whether calculated or collected, must be deployed on the same entity.

 

To consolidate data across the entity hierarchy for calculated indicators, you must also choose one of the following entity aggregation methods:

  • Recalculate in all levels: This method carry out a calculation at each entity level from lowest to highest using the indicator calculation formula.

     

    TIP  This method is recommended for percentages.

     

    Example

    Data collected before using an aggregation method:

    • The entity hierarchy contains three levels:

      • Group level: Group

      • Continent Level: Europe and Asia

      • Country level: France, Spain, China, and Japan

    • Indicator A and Indicator B are collected indicators. The chosen temporal aggregation is Sum.

    • Data is collected on indicators A and B at the Country level.

     

    Data consolidated using a temporal aggregation method:

    • Data is consolidated for indicators A and B at the Group and Continent levels, using the chosen temporal aggregation.

       

      For example, the calculated value on Europe is the sum of the collected values on France and Spain.

     

    Data calculated, then consolidated using an entity aggregation method:

    • Indicator C is a calculated indicator:

      • Its calculation formula is C = A/B.

      • The chosen entity aggregation method is Recalculated at all levels.

    • For indicator C, data is calculated using its calculation formula, then consolidated its chosen entity aggregation method:

      1. The calculation formula of indicator C is used at the Collect level.

         

        In our example, the calculated value for country entities is the collected or consolidated value of indicator A divided by the collected or consolidated value of indicator B.

      2. The chosen temporal aggregation method is used at the higher levels, namely the Group and Continent levels.

         

        The calculation formula of Indicator C is applied at all levels.

     

  • Compute at level 0 then aggregate: This method carry out a calculation at the data collection point, called Collect level in the CSR Insight application, using the indicator calculation formula, then aggregates to higher levels according to the chosen temporal aggregation method.

     

    NOTE

    Since the 2.12 version of the CSR Insight application, you no longer need to add the Consolidate calculation function to each item of the calculation formula when using the Compute at level 0 then aggregate aggregation method.

    The Consolidate calculation function is now implicitly applied in all calculation formulas that contains:

    • Indicator references but no calculation functions, or

    • The RetrievePrevYear, RetrievePrevMonth, RetrieveAggregation12Months or RetrieveAggregationYtd calculation function

    This means the calculation engine will automatically aggregate the items at lower levels across the entity hierarchy.

    This automatic calculation function, called AutoConsolidate, must be activated by the project team. You do not need to add it manually in your calculation formula.

    For more information on calculation functions, see the Calculation Functions appendix.

     

    • Example

    Data collected before using an aggregation method:

    • The entity hierarchy contains three levels:

      • Group level: Group

      • Continent Level: Europe and Asia

      • Country level: France, Spain, China, and Japan

    • The Country level is the chosen Collect level for all indicators.

    • Indicator A and Indicator B are collected indicators. The chosen temporal aggregation is Sum.

    • Data is collected on indicators A and B at the Country level.

     

    Data consolidated using a temporal aggregation method:

    • Data is consolidated for indicators A and B at the Group and Continent levels using the chosen temporal aggregation.

       

      For example, the calculated value on Europe is the sum of the collected values on France and Spain.

     

    Data calculated, then consolidated using an entity aggregation method:

    • Indicator C is a calculated indicator:

      • Its calculation formula is C = A/B.

      • The chosen temporal aggregation is Sum.

      • The chosen entity aggregation method is Compute at level 0 then aggregate.

    • For indicator C, data is calculated using its calculation formula, then consolidated using its chosen entity aggregation method:

      1. The calculation formula of indicator C is used at the Collect level.

         

        In our example, the calculated value for country entities is the collected or consolidated value of indicator A divided by the collected or consolidated value of indicator B.

      2. The chosen temporal aggregation method is used at the higher levels, that is the Group and Continent levels.

         

        In our example, the consolidated value for continent entities is the sum of the values of country entities of indicator C, and the consolidated value for the group entity is the sum of the values of continent entities of indicator C.
