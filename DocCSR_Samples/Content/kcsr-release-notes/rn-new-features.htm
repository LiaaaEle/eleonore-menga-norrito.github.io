New Features

On this page, you can find a list of new features.

Introduction

The 2.12 version of the CSR Insight application incorporates several enhancements, designed primarily in response to user feedback. These improvements aim to optimize the user experience, strengthen data quality, and improve configuration flexibility.

 

The main new features focus on the following aspects:

  • File export: Addition of global configuration to manage the display of technical columns (particularly the hidden ID column)

  • Indicator creation and management: Improved duplicate detection

  • Separation of screen access right from entity duplication right

  • New consistency check: Implementation of mandatory data entry control for numeric indicators and simple choice lists with visual alert in case of missing values

  • Security and alternative vision management: Restricted access to alternative vision entities based on user scope in reporting screens

  • Unit initialization: Preload the application with a default unit list along with their conversion factor values

  • Indicator identification and specific alerts related to the Carbon Footprint module: Introduction of the "Indicator used in carbon footprint" concept, with alerts in the Carbon Footprint Audit screen in case of:

    • An indicator not mapped to an emission factor,

    • An emission factor without value

  • Rewording of certain messages for better understanding of management rules such as for the Strategy Deployment screen

  • Improvement to the campaign settings audit file: Detection of deployment conflicts

 

Other new features and improvements are briefly described in this documentation.

File Export: Manage hidden technical columns

This functionality was designed to offer users greater flexibility while simplifying their experience.

 

A new global setting has been introduced in the Shuttle Studio: HideIdColumn

  • Default value: True → the "hidden ID" column is masked in exports.

  • Possible value: False → the column is visible in all exports.

 

This setting provides you the ability to customize their exports according to their needs, with or without technical columns, while avoiding manual configuration for each export.

 

Important points:

  • This setting applies globally to the entire application for all export types.

  • Backward compatibility ensured: During version upgrades, existing settings are automatically preserved.

  • Configuration is performed by the Professional Services team based on each client's needs.

Indicator Creation with Duplicate Checking Through Data Entry and Import

A verification has been added during indicator creation, whether through manual entry or import, to prevent duplication of already existing but deactivated indicators.

 

New features:

  • When a user attempts to create a new indicator with a label identical to that of an indicator already present in the database but currently deactivated, the system now displays an explicit error message.

  • This verification is automatically performed:

    • During direct indicator entry in the interface

    • When importing a file containing new indicators

 

 

This improvement avoids unnecessary duplicates in indicators and makes it easier to reactivate an existing indicator instead of creating a new one.

Separation of Screen Access Right from Entity Duplication Right

An important enhancement has been made to the management of rights related to entity duplication.

 

Previous behavior:

  • Access rights to the Entity Management screen automatically allowed entity duplication, without distinction from add rights

 

New behavior:

  • Entity duplication is now exclusively conditioned by the entity add right.

  • Screen access rights alone no longer allow this action.

 

User rights management on the Profile Matrix screen:

  • A user authorized to add an entity can also duplicate that entity.

 

Compatibility during version upgrade:

  • When updating to the 2.12 version, all users who already have the right to add an entity will automatically inherit the associated duplication right.

 

Purposes of this enhancement:

  • Strengthen granular control of actions authorized by profile

  • Clarify the distinction between consultation, creation, and duplication rights

  • Improve security and consistency in user permission management

Consistency Checks on Unentered Values

A new functional enhancement has been introduced regarding the management of numeric indicators as well as simple choice lists. A consistency check is now triggered whenever a required indicator is left empty.

 

Purposes of this new consistency check:

  • Encourage data completeness during collection

  • Strengthen data quality

 

Consistency check behavior:

  • An alert is automatically generated whenever an indicator is left empty, based on the type of control defined in the configuration.

    Three possible types of consistency check:

    • Validation freezing: The user is informed via an alert message that they must enter a value or validation will be blocked.

    • Mandatory comment: If the indicator is empty, the user is required to enter a comment justifying the absence of a value.

    • Mandatory attachment: The user must provide a supporting attachment if the indicator is left empty.

  • Authorized users can edit the consistency check type and delete an existing consistency check.

  • When the consistency check type for an indicator is Entry, the Thresholds column is automatically grayed out, that is non-modifiable, as it does not apply to this type of consistency check.

  • Consistency check visibility:

    • All consistency checks defined on indicators are displayed directly in the Data Collection Campaign screen ensuring immediate visibility for users during data entry.

    • Alerts are not visible when the campaign is launched. They appear when at least one indicator has been entered.

 

Impacted screens:

  • Home Screen: Global display of alerts

  • Alerts screen: Centralization of inconsistencies related to unfilled indicators

  • Data Collection Campaign screen: Direct visualization of consistency checks during data entry

Manage Security on Alternative Visions

A new feature now enables users to access reports according to alternative visions while strictly respecting their access scope.

 

Behavior:

  • When assigning user profiles, you can now grant access rights to entities belonging to one or more alternative visions.

  • The user only view entities belonging to their scope on reporting screens whether they belong to the main vision or an alternative vision.

 

This enhancement provides greater flexibility in data analysis according to different organizational perspectives and maintains strict access control while enriching reporting possibilities.

Addition of "All" in Drop-down Menus that Search for an Indicator

To save time during configuration and simplify indicator selection, a new improvement has been made to the ergonomics of drop-down menus.

 

You can now directly select the All option in the following drop-down menus:

  • Chapters

  • Themes

  • Sections

 

Impacted screens:

  • Strategy Deployment

  • Association of Emission Factors With Activity Indicators

  • Threshold Management

Unit Initialization

To save time during the initial configuration phase, a new feature enables to preload the application with a default unit list, along with their conversion factor values.

Enhancement details:

  • A standardized list of units (for example, kg, t, kWh, and so on) is now preconfigured in the application.

  • Each unit is associated with a conversion factor to facilitate calculations and comparisons.

  • This configuration is integrated directly into the starter kit provided when opening a new project.

 

This improvement reduces project implementation time for business teams and standardizes measurement unit practices from startup.

New concept: Indicator Used in Carbon Footprint

A new enhancement has been introduced in the Carbon Footprint column of the Indicator Management screen, to more clearly identify indicators used in carbon footprint calculations and strengthen the consistency of associations with emission factors.

 

Behavior:

  • If the user identifies the indicator as used in carbon footprint without having associated an emission factor, an alert displays to signal the missing correspondence on the Carbon Footprint Audit screen.

  • Export as well as import has been updated by adding a new Used in carbon footprintcolumn:

    • For non-numeric indicators, the column displays - in the exported file as well as in the display grid.

    • For non-numeric indicators:

      • The value must be left empty in the file.

      • If an association between an indicator and an emission factor is created through the Association of Emission Factors and Activity Indicators screen, the concerned indicator is automatically marked as Used in carbon footprint.

 

During version upgrade, All active activity indicators already associated with an emission factor will be automatically marked as Used in carbon footprint.

 

On the Carbon Footprint Audit screen, an alert icon is displayed next to each indicator identified as used in carbon footprint but not yet associated with an emission factor.

 

In the Carbon footprint block of the Identity card, on Indicator Management screen, a switch button has been added to identify the indicator as used in carbon footprint or not.

Alert on Emission Factors without Values

A new visual alert has been introduced to strengthen data quality within the Carbon Footprint module by signaling emission factors associated with an activity indicator but without entered values.

An alert icon displays next to any emission factor linked to an activity indicator when no value is entered.

 

Quick navigation:

  • A magnifying glass icon is also displayed next to the concerned emission factor.

  • Click this magnifying glass to be directly redirected to the Emission Factor Valuation screen.

Strategy Deployment Screen: Improvement of Labels related to Date Control

Messages and labels relating to date control have been reviewed to make them more explicit and understandable for users. This improvement concerns all strategy deployment levels.

 

This improvement facilitates understanding of date validation rules and reduce entry or planning errors related to ambiguous messages.

Improvements to the Campaign Settings Audit File

The excel file exported for auditing the campaign settings has been improved:

  • Tabular format: Improved readability and option to sort by columns

  • Detection of deployment conflicts:

    • The file highlights cases where a specific deployment overrides another deployment inherited from an entity.

    • These situations are clearly identified, facilitating their detection and resolution.

Make Consolidate Implicit when Retrieving Data in Calculation Formulas

The project team can now activate a new automatic calculation function through the Studio settings to implicitly consolidate data on calculated indicators: AutoConsolidate.

 

Before activating AutoConsolidate on an existing environment, it is strongly recommended to run a configuration audit to verify that no conflicts exist between parent and child deployments. In case of unresolved conflicts, activating AutoConsolidate mode could lead to a risk of data double counting.

 

For more details on AutoConsolidate, see the Calculation Functions documentation.
