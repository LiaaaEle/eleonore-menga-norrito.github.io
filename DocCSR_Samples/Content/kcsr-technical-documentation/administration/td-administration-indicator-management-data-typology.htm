Security Notes

Some actions, such as screen access, are permitted only for authorized users, that is, users with the appropriate profile. In other words, if the user does not have the right profile, the user cannot perform the action.

To configure this security (also called user rights), complete the following steps:

  1. Define the profiles in the Profile Management screen.

  2. Define users and attach one or more profiles to them in the User Management screen.

  3. Assign user rights to the desired profiles in the Profile Matrix screen.

The Data typology column contains data typology items for each indicator:

Item Description

Data source

Data source of an indicator:

  • Collected: Indicator data is collected on the Data Collection Campaigns screen.

  • Calculated: Indicator data is calculated via a formula.

NOTE For calculated indicators, you can use calculation functions in formulas. For more information, see the Calculation Functions appendix.

Calculation scope

Defines the deployment behavior of calculated indicators:

  • Manual: You must manually deploy the indicator on entities within campaigns on the Campaign Settings: Entities to Deploy for an Indicator screen, then manually start the calculation.

  • Automatic: The indicator is automatically deployed, then calculated. No manual intervention is required.

    NOTE Automatic deployment occurs at the most granular level when all dependencies are present. Calculation functions are not supported.

 

Default behavior depends on when the indicator was created:

  • Existing indicators, created in versions of the CSR Insight application versions prior to the 2.13 version, keep their usual deployment behavior. They are deployed and calculated manually.

  • New indicators, created in the 2.13 version of the CSR Insight application and later versions, are automatically deployed and calculated upon creation.

 

NOTE Changing the calculation scope of an indicator results in the deletion of all its data and triggers its recalculation.

Response type

Type of data that can be collected for the indicator:

  • Numerical data: Collected data is numeric.

    NOTE For calculated indicators, Numerical data is the only selectable option.

  • Choice list – simple choice: One value among a choice list can be selected for the indicator. Collected data is numeric or textual.

    NOTE A predefined list of choices must be created on the Choice List Management screen before being associated to the indicator.

  • Choice list – multiple selection: Multiple values among a choice list can be selected for the indicator. Collected data is numeric or textual.

    NOTE A predefined list of choices must be created on the Choice List Management screen before being associated to the indicator.

  • Text: Collected data is textual.

  • File: Collected data is a file.

Unit category

Category of the default unit selected for the indicator.

NOTE To manage unit categories, see the documentation on Unit Category Management.

Unit

Unit in which the indicator data is collected or calculated by default. Also called default unit.

NOTE To manage units, see the documentation on Unit Management.

Magnitude

NOTE Only for monetary indicators.

Used for data entry, calculation, display, import and export.

Always editable even if data was entered.

Order of magnitude for the financial amounts entered on the Data Collection Campaigns screen:

  • K currency: Conversion factor = 1,000

  • M currency: Conversion factor = 1,000,000

  • B currency: Conversion factor = 1,000,000,000

 

The entered value is multiplied by the order of magnitude and stored in currency unit.

Example

"Purchased electricity" is a monetary indicator. To collect data in thousands of euros (K€), you must select Euro as the unit, then K currency as the order of magnitude, on this screen.

When you enter 10 K€ on the Data Collection Campaigns screen, the stored value will be 10,000 €.

Rate Type

Exchange rate type of a monetary indicator:

  • Average rate: Rate entered by the administrator, for example for the flow-type indicators.

  • End-of-currency rate: Rate entered by the administrator to calculate an indicator, for example in the case of an investment or a stock.

Exchange rates are used for currency conversion.

Changeable unit

Feature that only concerns numerical indicators.

 

Indicates if the indicator unit is changeable or not on the Data Collection Campaigns screen:

  • Yes: The indicator unit is changeable.

  • No: The indicator unit is not changeable.

 

NOTE

In the CSR Insight application, you can use three types of units:

  • The default unit

  • The input unit: the unit of the data entered for the indicator

  • The preference unit: the unit your entered data will be converted to

 

Collect level

Each indicator is attached to an entity type, also called data collection point. This entity type contains a set of entities on which data will be collected by default for the indicator.

 

Allows you to quickly associate an indicator to all entities with the same data collection level when creating a data collection campaign.

 

You can select one or more data collection points.

NOTE The indicator is automatically deployed on entities at the selected data collection points as long as consistency rules are followed.

For more details on consistency rules, see Campaign Settings.

Frequency

Allows you to quickly associate an indicator to all periods on which data will be collected or calculated when creating a data collection campaign.

Periodicity of indicator data:

  • Yearly: Data is collected or calculated once a year.

  • Semiannually: Data is collected or calculated twice a year (once in the first semester, once in the second semester):

    • HY1 (Half Year 1) period: First half of the year (first semester)

    • HY2 (Half Year 2) period: Second half of the year (second semester)

  • Quarterly: Data is collected or calculated four times a year (once in the first quarter, once in the second quarter, once in the third quarter, once in the fourth quarter):

    • Q1 period: First quarter

    • Q2 period: Second quarter

    • Q3 period: Third quarter

    • Q4 period: Fourth quarter

  • Monthly: Data is collected or calculated twelve times a year, that is once a month:

    • January period

    • February period

    • March period

    • April period

    • May period

    • June period

    • July period

    • August period

    • September period

    • October period

    • November period

    • December period

 

Formula

Formula used to calculate data for a calculated indicator.

You can add calculation functions in your formula.

NOTE

Since the 2.12 version of the CSR Insight application, you no longer need to add the Consolidate calculation function to each item of the calculation formula when using the Compute at level 0 then aggregate aggregation method.

The Consolidate calculation function is now implicitly applied in all calculation formulas that contains:

  • Indicator references but no calculation functions, or

  • The RetrievePrevYear, RetrievePrevMonth, RetrieveAggregation12Months or RetrieveAggregationYtd calculation function

This means the calculation engine will automatically aggregate the items at lower levels across the entity hierarchy.

This automatic calculation function, called AutoConsolidate, must be activated by the project team. You do not need to add it manually in your calculation formula.

For more information on calculation functions, see the Calculation Functions appendix.

 

Entity aggregation

Data consolidation method on entity hierarchy for calculated indicators:

  • Recalculate in all levels

  • Compute at level 0 then aggregate

 

For more details on entity aggregation methods, see Indicator Management: Aggregations.

Temporal aggregation

Data consolidation method on period and entity hierarchies:

  • Average

  • Sum

  • Minimum

  • Maximum

  • Last known value

  • Last known value including empty values

  • Uncertainty (absolute value) (generally used with negative numbers)

  • Average excluding null values (0)

 

For more details on temporal aggregation methods, see Indicator Management: Aggregations.

 

From the Data typology column, you can Edit Data Typology for an Indicator.

 

The Data typology block in the Identity card has the same content as the Data typology column. To access the Identity card, see Edit an Indicator.

Edit Data Typology for an Indicator

There a two ways to edit data typology for an indicator:

  • From the Identity Card

  • From the Data Typology Column

From the Identity Card

To edit data typology from the Identity card:

  1. Make the Identity card appears for the desired indicator as indicated in the Edit an Indicator section.

  2. Go to the Data typology block.

  3. Edit the information as desired.

  4. Click Save at the top right of the Identity card.

From the Data Typology column

To edit data typology from the Data typology column:

  1. Position your cursor at the line of the indicator for which you want to edit data typology.

  2. Find the sub-column that corresponds to the data typology item you want you want to edit.

  3. Double-click the cell in this sub-column.

  4. Edit the information contained in the cell.

  5. Click the button at the top right of the nested grid.

  6. Repeat the same steps for each data typology item you want to edit for the indicator.
